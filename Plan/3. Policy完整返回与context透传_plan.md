# Plan 3. Policy 完整返回与 context 跨页片段透传

## 状态
已完成（分支 `feature/supervisor-scheduler`）

## 目标
落实队友联调要求：保留 `PolicyRetriever.search()` 完整返回（尤其 `status`、`year_filters`、`requires_*_clarification`），并把 `context()` 取到的跨页相邻片段连同证据 ID 一起传给下游。

## 需求→步骤映射
| 需求（队友） | 步骤 | 出口校验 |
|---|---|---|
| 保留完整 search() 返回，不只传 results | `build_policy_search` 用 `dict(response)` 浅拷贝，逐键保留；只替换 `results`/`limitations` | 测试逐键断言原字段；真实索引断言 status/year_filters/5 个 flag 全在 |
| 学年/批次追问信息不丢 | `status`→`policy_status`、`year_filters`→`policy_scope`、所有 True 的 `requires_*_clarification`→`clarification_flags`（agents.collect_evidence 既有逻辑） | 端到端断言三个 payload 字段；有 flag 时 Supervisor 返回 `clarification_required` 且不展示 answer |
| 跨页条件用 context() 相邻片段+证据 ID | 对 top N results 调 `retriever.context(anchor)`，把未出现过的片段以完整 evidence 记录追加（`origin=context`、`anchor_evidence_id`、`warnings`） | 真实索引 COMP5926 追加 1 条 `polyu_extended_..._p002_...`；测试断言 ID 与字段 |
| 不能破坏 collect_evidence 的 ID 唯一约束 | 用 `seen` 集合按 evidence_id 全局去重（含 context 自引用与其他锚点重叠） | 去重用例断言 `collect_evidence` 无 Conflicting evidence ID |
| context 失败不能拖垮分支 | 捕获 context 异常，写 limitation 降级 | context_error 用例断言 status 仍 candidates_found |
| 不硬依赖 Part1 包路径 | duck typing，只要求 `search()` 存在、`context()` 可选 | 假 retriever 测试；真实联调时从包外注入 retriever |

## 关键决策
- `context_limit=3`：只对最高排名 3 条取相邻片段，避免宽查询把 evidence 膨胀；可用参数调整，`include_context=False` 完全关闭。
- context 片段保留原 `citation`（含 title/pdf_page/source_url），只追加 warning 和 origin 元数据，满足 `collect_evidence` 的必填校验。
- 不修改 `status`/`year_filters`/`requires_*`：这些由队友检索结果决定，适配层不做推断或覆盖。
- `build_policy_search` 返回闭包，签名 `(query) -> dict`，直接可传给 `supervisor.run(policy_search=...)`。

## 边界与失败模式
| 失败模式 | 处置 |
|---|---|
| `context()` 抛 KeyError/超时 | 计数降级，写 limitation，保留原结果 |
| context 返回自身片段 | 按 evidence_id 去重跳过 |
| 多锚点 context 片段重叠 | 全局 seen 集合去重 |
| context 片段缺 text 或 citation.title | 跳过该片段 |
| `search()` 返回非 dict | 抛 ValueError，由 Supervisor 标记 failed |

## 二阶效应
只读调用 `search()`/`context()`，不改队友索引、脚本或交付包；对同一 retriever 复用（PolicyRetriever 构造一次）。
