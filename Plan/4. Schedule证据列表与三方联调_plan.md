## 关键决策
- 不做来源解析器，只做契约归一化：`build_schedule_search(fetch)` 把「取数」留给 Schedule 同学，本层只保证出参合规；这样 eStudent/Canvas/本地 fixture 都能接。
- 日期型事件（只有 date 无 time）不编造 `00:00`：`start_at` 直接省略 + 写 warning，`text` 只到日期。宁可少一个字段，也不给 Verifier 一个假时间。
- 无时区时间戳统一按 `Asia/Hong_Kong (+08:00)` 补齐，但必须写进 `warnings`，让 Verifier 知道这是假设而非来源事实。
- ID 冲突不是覆盖而是加内容哈希后缀：同课程同时间的两个不同地点是两个真实事件，不能被去重吃掉；真正重复投递（内容签名相同）才折叠，并计入 `stats["duplicates"]`。
- `stats` 只作可选出参（`assumed_timezone` / `duplicates` / `stripped` / `skipped`），不改变返回类型，保持「列表」契约。

## 边界与失败模式
| 失败模式 | 处置 |
|---|---|
| 时间戳无法解析 | 抛 `ValueError` → Supervisor 标 failed，不拿编造时间作答 |
| 行既无时间也无地点/类型 | 跳过并写入 `stats["skipped"]` |
| 取数函数抛异常 | 原样上抛，Supervisor 记 failed 并提示「日程查询失败」 |
| 源里带 token / 学号 / 邮箱 | 白名单丢弃，`stats["stripped"]` 计数 |
| 同一事件重复投递 | 内容签名相同则去重 |
