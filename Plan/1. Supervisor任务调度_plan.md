# Plan 1. Supervisor 任务调度实现

## 状态
已完成（分支 `feature/supervisor-scheduler`）

## 目标
在队友交付的 `agents.py`（Answerer/Verifier）之上实现 Supervisor 调度层：按 Planner 计划调度 Policy/Schedule 分支，按 `INTEGRATION.md` 示例依次调用 `collect_evidence → answer → verify`，按 Verifier 状态决定展示/重写/补查/追问，绝不把未验证草稿当最终答案。

## 需求→步骤映射
| 需求（来源） | 步骤 | 出口校验 |
|---|---|---|
| Planner 给原始问题+分支+子查询；Answerer/Verifier 收到同一完整问题（INTEGRATION:7） | 写入 `run(plan, ...)`，`question` 只取 `plan["question"]` 并原样传递 | 测试断言两次 model 调用的 payload.question 相等 |
| Policy 传完整 search 字典（INTEGRATION:8） | 分支返回原样透传给 `collect_evidence`，不裁剪字段 | 测试断言 payload 含 year_filters/limitations/clarification_flags |
| Schedule 传证据列表（INTEGRATION:11-29） | 列表原样透传 | 混合查询断言两种来源均可展示 |
| 三态区分：未调用/成功空/失败（INTEGRATION:9） | `states[name]["state"] = not_called/empty/ok/failed` | 单查测试断言未请求分支为 not_called |
| 捕获检索/模型异常、记录失败分支、每题最多重试一次（INTEGRATION:9, README:15） | `_dispatch` 捕获分支异常；`run` 共享 retry 计数；仅 `rejected`/分支失败/模型异常可重试一次 | 失败分支、重试成功、模型异常三条用例 |
| 按示例依次调用两个模块（INTEGRATION:37-39） | `collect_evidence → answer → verify(policy_gate=...)` | 全部通过用例 |
| 通过才展示 answer+sources；其他状态走 issues/unanswered/flags（INTEGRATION:44-49） | `_decision` 仅 approved 时带 answer/sources | 资料不足/矛盾/澄清用例断言无 answer 字段 |
| 兼容当前根目录 `agents.py` 与打包 `answer_verifier/`（INTEGRATION:42） | try 包导入 except 根导入 | 两种导入路径均实际运行 |
| 不泄露 Canvas token/个人资料（INTEGRATION:29） | 错误信息脱敏，notice 只带异常类型 | 脱敏用例 |

## 关键决策
- 分支通过注入 callable（`policy_search` / `schedule_search`）执行，不硬依赖队友尚未提交的模块；这样 Supervisor 可单测且不碰 Canvas token。
- 重试计数在整题共享，上限 1：分支失败重试、Verifier `rejected` 重写、模型异常各占同一配额，避免同题多次重试。
- `insufficient_evidence` / `clarification_required` 不自动重试（属于补证据/追问，需 Planner 或用户介入），直接返回可操作状态。
- 未验证草稿绝不进入返回值任何字段。

## 边界与失败模式
| 失败模式 | 处置档 |
|---|---|
| 分支 callable 抛异常 | 放行+标记：state=failed、notice 告知用户、可用证据继续；有一次重试配额 |
| model/verify 抛异常 | 放行+标记：status=model_error、无 answer |
| draft 结构非法 | 由 agents.verify 返回 rejected，本层不重复校验 |
| 非法 plan.question / 未知分支 | 拒绝：ValueError |
| 错误串含 token/api_key | 脱敏后只保留类型+截断消息 |
